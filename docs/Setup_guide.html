Introduction: Intelligent Demo Orchestrator (IDO)

The Intelligent Demo Orchestrator (IDO) is an AI-powered automation tool that transforms demo setup from days to minutes. It enables:

  • Rapid Provisioning: Instant system readiness.
  • Realistic Data: Auto-populates industry-specific records.
  • Tailored Context: Customizes categories, workflows, and use cases for clients.

How It Works

1. Hybrid Architecture (Split Runtime)

The orchestrator is split across two runtimes so each side does what it's good at. You don't need to memorize this — but understanding it explains why deployment has two artifacts.

Why split? Bulk delete and CSS regex are dramatically faster as one server-side transaction than as N REST calls. Everything else is just as cheap (and far easier to debug) over REST.

Dashboard injection — first-column traversal: Instead of hardcoding sys_id references, the MCP traverses the portal layout dynamically:

  1. Queries sp_page where id is index (or whatever pageId the caller specifies).
  2. Queries sp_column with sp_row.sp_container.sp_page=<page>^ORDERBYorder, limit 1, to find the primary content column (top order).
  3. Creates an sp_instance record mapping the target widget (e.g. demo_kpi_dashboard) to that column. The sp_widget records themselves must already exist on the instance — Update Set / scoped app — the MCP only manages bindings.

2. Prerequisites

  • Node.js

    Install Node.js 18+ from nodejs.org.

  • Claude or Cursor (desktop)

    MCP needs the desktop app: Claude or Cursor. Accenture: Get Cursor on myASG.

  • ServiceNow instance

    A developer or sub-prod instance where you can sign in as admin (or equivalent) to deploy the scripted REST pieces.

3. The Local MCP Server

  • Clone and install

    demoenvservicenowmcp — clone it, then in that folder:

    git clone https://github.com/vbiyani3107/demoenvservicenowmcp cd demoenvservicenowmcp npm install

  • Set your ServiceNow login

    Open config/servicenow-instances.json. Under instances, edit the dev entry: set url (full https://… URL), username, and password. Save the file. Use the same values in the next section’s SERVICENOW_* env vars when you register the MCP server.

4. Claude/Cursor Configuration

  • Open your MCP config file

    Claude Desktop: %APPDATA%\Claude\claude_desktop_config.json (Windows) or ~/Library/Application Support/Claude/claude_desktop_config.json (Mac).

    Cursor: ~/.cursor/mcp.json or the project’s .cursor/mcp.json (or Settings → Features → MCP).

  • Register this MCP server

    Add an entry that runs Node on this repo’s src/stdio-server.js (replace with the absolute path to your clone). Include ServiceNow login in env — use the same URL, username, and password as in step 2.

    { "mcpServers": { "servicenow-demo": { "command": "node", "args": [ "/absolute/path/to/demoenvservicenowmcp/src/stdio-server.js" ], "env": { "SERVICENOW_INSTANCE_URL": "https://YOUR_INSTANCE.service-now.com", "SERVICENOW_USERNAME": "admin", "SERVICENOW_PASSWORD": "YOUR_PASSWORD" } } } }

    Env-only setup: If you prefer not to use servicenow-instances.json, remove or rename that file and rely on these three variables (or the same names in a root .env). With the default repo layout, the server reads config/servicenow-instances.json first — keep values aligned with env so nothing drifts.

  • Restart and check

    Quit and reopen Claude or Cursor. Start a chat and ask it to list ServiceNow tools — you should see tools like SN-Deploy-Demo.

6. Running the Engine

Ask Claude or Cursor in plain language to deploy or extend a demo — it calls the ServiceNow tools for you.

Available demo tools

SN-Deploy-Demo — one-call umbrella. Composes everything below in a single payload. Use this 95% of the time.

For surgical edits Claude can also call any of these directly:

  • SN-Demo-Apply-Branding — visual branding (CSS + base64 logo + optional hero container background)
  • SN-Demo-Apply-Personas — users + roles
  • SN-Demo-Apply-Data — incidents, plus optional HR cases (sn_hr_core_case) and purchase orders (proc_po), plugin-gated
  • SN-Demo-Apply-Catalog — categories + catalog items + variables + choices
  • SN-Demo-Apply-Widget-Overrides — relabel sp_instance widget titles
  • SN-Demo-Apply-Reports — sys_report rows used by demo dashboards (idempotent on title)
  • SN-Demo-Apply-Dashboard — bind existing sp_widget records to the index page's first column as sp_instance rows; clientPrefix-stamped for clean revert
  • SN-Demo-Revert — bulk teardown by clientPrefix (server-side deleteMultiple())

Delete a demo

Copy into Claude or Cursor to remove a deployed demo. (Replace PREFIX with your client prefix e.g., MCD, WMT, MED).

Delete the ServiceNow demo for the client with prefix: PREFIX. Run SN-Demo-Revert with clientPrefix PREFIX first, then remove any remaining demo data — incidents, users, catalog categories or items, portal widgets, branding, and logo changes — until the demo is fully gone from the instance.

Use Cases

The following use cases are fully supported and verified with this demo orchestration tool:

Use Case Description
Dummy / Test Data Population Populate a ServiceNow instance with synthetic records (incidents, requests, users, CIs) without Demo Hub or z-boot.
Client Logo Replacement Swap the default ServiceNow logo with the client's branding across the portal banner and UI header.
Color Scheme / Theme Customization Update primary, secondary, and accent colors to align with the client's brand guidelines.
Terminology & Label Substitution Replace generic labels with client-specific terminology (e.g. Employee becomes Crew Member for McDonald's).
Industry-Specific Category & Reference Data Populate catalogue categories and reference tables with industry-relevant data (e.g. sourcing categories for a Procurement demo).
Industry-Specific Pre-Built Request Templates Create tailored demo requests for the client's vertical (e.g. ordering store equipment and cooking supplies for McDonald's).
Widget Header & UI Relabelling Update portal widget headers and column titles to match the audience's functional area (e.g. sourcing labels for Procurement).
Full Client-Specific Demo Environment Package Bundle all customisations (data, branding, terminology, categories, templates) into a single deployable package per client.
Persona-Based Role & User Configuration Configure demo users with personas aligned to the client's org structure - titles, departments, approval hierarchies, and data visibility.
Automated Demo Environment Provisioning Build a pipeline that spins up a client-configured instance on demand from a config file, with no manual setup per demo.
